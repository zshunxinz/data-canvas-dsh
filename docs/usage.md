# 使用说明

为 DeepSeek Harness 智能体提供一个可长期保存分析结果的地方：**多个画布、图表 / 表格 / 指标 / 文字 / 代码卡片，以及可导入和查询的本地数据源**。你可以用鼠标整理布局，也可以在数周后继续查看。

这是一个 DeepSeek Harness 插件。无需额外账号、远程服务或网络连接；画布、导入数据和查询结果都保存在本机插件目录中。

## 解决什么问题

聊天适合快速得到答案，却不擅长长期保存结果。你询问趋势、得到图表、继续向下聊天，过一天就很难再找到它。

这个插件把分析与持久化呈现分开：

- **智能体负责分析和编排。** 它可读取文件、运行代码计算，也可调用本地数据源工具执行轻量结构化查询，再把结果写入画布。
- **插件负责本地数据、画布和呈现。** 它保存数据源、查询结果、画布、卡片和布局，并提供可视化工作区供你浏览和整理。

## 范围：插件提供画布和受限的本地数据查询

DeepSeek Harness 可使用代码执行完成复杂计算。本插件也支持导入 CSV / XLSX，并通过受限的结构化查询选择、过滤、分组、聚合和排序；查询接口不执行任意 SQL 或代码。

```text
CSV / XLSX → 导入本地数据源 → 结构化查询 → 保存结果快照 → 加入画布
文件 → 智能体读取并运行代码 → canvas_add_card → 保存到画布
```

查询结果会保留源数据版本、查询口径和完整性状态，便于复核。复杂统计和超出导入限制的数据仍适合由智能体代码处理。

## 溯源与追问

每张数据卡现在带有**不可变的数据版本**与**来源图**，界面从「一段说明文字」变成可核对的记录：

- **计算**：原生结构化查询显示真实口径与结果快照，可**只读复算**比对结果哈希；模型自算的卡片只有在显式引用某次已完成调用时才显示脱敏原文，并标为「待核对」——不会把同轮相邻脚本当成来源。生成 SQL 从来不会被宣称为已执行。
- **数据**：显示当时的源名称、文件、行数与列数；当前数据源内容变了会标「当前源已变更」，仍可打开**计算时版本**（只读分页）。
- **会话**：记录产生该版本的真实会话与调用，可跳回会话；找不到活跃 Agent 不等于会话被删除。
- **版本**：改数字或映射会产生新数据版本；只改标题、颜色、尺寸、位置**不**产生新版本。旧版本可只读查看，历史对话里的卡片仍显示写入时的图。
- **追问**：从画布卡片或对话图卡发起，固定点击时的数据版本，把短引用追加到当前会话输入框；不覆盖草稿、不自动发送，交付状态以编辑器确认为准。
- **校验与复算**：「校验」只读，检查结果哈希、源哈希、计数完整性与图表真实值；「复算」用保存的输入与方法重算，不保存新结果、不改卡片。

相应工具：`canvas_trace`（read / check / recompute / version）、`canvas_followup_context`；`canvas_add_card` / `canvas_update_card` / `canvas_add_result` 新增可选 `followup_id` 与 `calculation_ref`。

## 数据源引用

数据源和查询结果可以直接**递进对话**，用完留下可反查的使用记录：

- **在对话中使用**：选中数据源或切到「查询结果」时，页头/结果操作区出现这个按钮。点击后输入框追加一行短引用，例如 `@cardata（1,400 行）[xcharts:ds:<id>@<哈希>]`；不覆盖你已写的草稿，也不自动发送。
- **引用是版本化指针**：带内容哈希的引用固定"计算时那一版"；数据源后来改动，引用解析仍按当时版本读取，并标出「当前源已变更」。引用不携带数据行，也不代表授权。
- **使用情况**：数据源行菜单 →「使用情况」，列出用过它的卡片与会话（可点跳转）；删除确认会提示"被 N 张卡片、M 次对话使用"。
- **Agent 侧**：`xcharts_context` 按引用读取有界上下文（身份/字段/最多 20 行样本/列统计/结果口径），system prompt 要求先解析引用再回答。

上面这些记录只落在插件本地 `usages/`（按月文件、只记引用与动作、不记数据行），可安全删除重建索引。

## 数据解析

导入不再要求文件"恰好标准"，常见导出问题会被修复并在数据源页说明：

- **缺失值**：`?`、`NA`、`N/A`、`NULL`、`None`、`NaN`、`NIL`、空串 → 空值；因此含 `?` 的数值列仍是数值列。要保留原样传 `missing_values: 'keep'`，也可给自定义标记数组。
- **表头**：重复名自动加 `_2`，空表头生成「列N」，数据比表头宽时按「列N」补齐；BOM 与零宽字符清理。
- **分隔符与编码**：逗号/分号/制表符/竖线自动嗅探（支持 `.tsv`）；编码自动识别 UTF-8/UTF-16/GB18030/Windows-1252。显式传 `delimiter`/`encoding` 时以参数为准。
- **数值**：千分位、货币符号、会计括号负数、`.5`/`5.` 均可读为数值；前导零编号、超安全整数范围保留为文本。
- **Excel**：无缓存结果的公式与错误单元格按空值导入并给出单元格地址；用 `sheet` 可指定工作表（默认第一个）；日期格式的数字单元格按序列号换算。
- **日期**：`2024-01-02`、`2024/1/2`、`2024.1.2`、`2024年1月2日`、带时间的写法都识别为 `date` 列并归一为 ISO；分组可用 `{column, granularity}`（日/月/季/年），查询构建器勾选日期列时出现粒度选择；日期列支持比较筛选与 `min/max`。
- **告警**：编码回退、分隔符识别、缺失值数量、表头修正、公式空值都会显示在数据源页「解析提示」，并随查询结果来源备注保留。

## 数据源扩展

「新增数据源」按钮打开一个两页签弹窗：

- **文件**：拖拽或点击，支持 CSV / TSV / XLSX / **Parquet**；导入后的快照、查询、落卡、溯源与之前一致。
- **数据库**：MySQL / PostgreSQL，填主机/端口/库/用户/密码，可先「测试连接」（返回版本与延迟），保存后直接查询。

数据库数据源的要点：

- **只读 SQL**：面板里写 `SELECT`/`WITH`/`SHOW`/`EXPLAIN`，服务端强制只读事务、单条语句、拒绝写/DDL/`COPY`/`SET`，自动加 `LIMIT` 与 15 秒超时；结果是查询时快照（可落卡、可被对话引用）。
- **密码永不进入模型**：凭据用 AES-256-GCM 存在 `secrets/`，主密钥是 `secrets.key`（0600，或环境变量 `XCHARTS_SECRET_KEY`）；数据源 JSON、列表、工具输出、日志、备份、导出文件里都没有密码。Agent 用 `datasource_query` 的 `sql` 字段查询，不能创建连接、也拿不到密码。
- **联动**：卡片溯源显示 SQL 原文与实时连接（主机打码）；复算重跑 SQL 并标 `live_changed`，不覆盖快照；备份只带连接元数据，换机导入后需重填密码。
- **依赖**：`pg`、`mysql2`、`hyparquet`、`hyparquet-compressors` 已随插件目录安装。

## 备份

设置 →「备份」页，导出与导入都是真实操作：

- **导出备份**：把全部画布（单画布备份格式，内含卡片数据与来源说明）与全部布局模板打成一个 JSON 下载；文件名形如 `xcharts-backup-2026-10-17-08-30-00.json`。
- **导入备份**：选文件 → 确认 → 逐条校验后**新建**画布与模板，不覆盖现有内容；完成后显示导入数量与被跳过的条目。
- **范围**：数据源原始表格不在备份里（画布卡片的数据是内联保存的）；原始表请从原文件重新导入。单次最多 100 张画布 / 200 个模板，整包上限 8 MiB。

## 设置

画布「设置」与 Harness 自己的设置弹窗同构：左侧分页、右侧行式设置（标题 + 说明，右侧控件）。

- **显示**：拖拽吸附、超大画布、类型标签三个开关；重置缩放与导出说明各占一行。
- **存储**：见下节（位置、占用、清理）。
- **关于**：当前版本、最近更新（弹出随包 CHANGELOG）、更新日志文件名。

## 存储占用

插件的数据都在一个目录里，位置由宿主决定，换电脑自动跟着变：

- **位置**：画布「设置」弹窗常显存储根目录（默认 `$DSH_HOME/storages/xcharts-canvas`，即通常的 `~/.dsh/storages/xcharts-canvas`；也可在插件配置里用 `storagePath` 指定），标注「默认路径 / 自定义路径」，可复制。
- **占用**：按目录列出画布、数据源、查询结果、撤销历史、版本快照、调用证据、追问引用、使用记录的文件数与大小，以及合计。
- **清理**（可安全执行，不影响数据本身）：
  - 撤销历史：删掉所有画布的撤销记录，画布内容不变；
  - 调用证据：删掉工具调用证据，溯源里对应条目显示为未留存；
  - 使用记录：删掉数据源/结果的引用使用记录；
  - 版本快照：删掉历史内容快照，带哈希的引用会回退到当前内容。
- 清理只允许这四个目录，接口层拒绝其它目标与路径穿越；清理前有确认，清理后显示释放的空间。

## 安装

更新插件后，必须完整安装并重启 DSH；只替换浏览器 bundle 会让旧插件路由继续留在内存中。

本插件是标准 DSH bundle。先构建 tarball，再安装到指定 profile：

```sh
pnpm pack
npx @deepseek-ai/dsh plugin --profile <your-profile> add ./data-canvas-dsh-0.10.20.tgz
npx @deepseek-ai/dsh --profile <your-profile>
```

包名版本应与 `package.json` 一致。`pnpm pack` 会通过 `prepack` 自动构建 `client.js`；更新 ECharts 依赖后，先运行 `pnpm build:echarts` 生成随包发布的 `client.echarts.js`。安装后重启 profile，因为启动时会缓存 manifest。可通过以下命令确认配置层已加载：

```sh
npx @deepseek-ai/dsh --profile <your-profile> --dump-config
# 预期输出中包含：  # == data-canvas-dsh
```

卸载插件：

```sh
npx @deepseek-ai/dsh plugin --profile <your-profile> remove data-canvas-dsh
```

## 工具

插件注册 13 个智能体工具：7 个画布工具，以及 6 个本地数据源 / 查询结果工具。

### 画布工具

| 工具 | 用途 |
|---|---|
| `canvas_list` | 列出画布（ID、名称、卡片数、更新时间） |
| `canvas_create` | 创建画布 |
| `canvas_read` | 读取画布卡片、布局和来源信息 |
| `canvas_add_card` | 添加图表、表格、指标、文字或代码卡片 |
| `canvas_update_card` | 修改卡片数据、标题或来源口径 |
| `canvas_remove_card` | 删除卡片 |
| `canvas_arrange` | 整理布局，使卡片紧密排列 |

### 数据源与查询结果工具

| 工具 | 用途 |
|---|---|
| `datasource_list` | 列出已导入数据源及字段摘要，不返回完整行数据 |
| `datasource_import` | 通过文件内容的 base64 导入 CSV / XLSX；不接受本机路径 |
| `datasource_describe` | 分页读取数据源预览和字段信息 |
| `datasource_query` | 对已导入数据执行受限的结构化查询，不执行任意 SQL |
| `analysis_read_result` | 分页读取查询结果、源数据版本、查询口径和完整性状态 |
| `canvas_add_result` | 将已保存的查询结果转换为图表、表格或指标卡并加入画布 |

工具返回精简 JSON；失败时会返回 `{ ok: false, code, error, suggestion }`，以便模型根据错误修正请求。画布写操作可传入 `expected_revision`；若期间有并发修改，操作会以 `REVISION_CONFLICT` 拒绝，而不会静默覆盖数据。

`datasource_query` 默认最多保存 1,000 行，允许将上限设为 5,000 行。响应只直接带回首批结果；使用 `analysis_read_result` 分页读取物化结果。通过 `canvas_add_result` 制图时，查询结果必须完整且不超过 500 行；超限时应先过滤或聚合。

## 文件保存位置

```text
$DSH_HOME/storages/xcharts-canvas/
  index.json                  画布目录
  canvases/<id>.json          画布元数据、卡片和布局
  history/<id>.json           每张画布最多 50 步的撤销 / 重做历史
  templates/<id>.json         布局模板
  datasources/<id>.json       导入后的规范化表格数据
  results/<id>.json           查询结果快照及来源口径
  .seeded                     首次示例画布已初始化标记
```

数据文件使用普通 JSON，并通过暂存文件和原子重命名写入。复制整个存储目录可以备份本地画布、数据源、查询结果、模板和历史。单独导出的画布 JSON 备份不包含原始数据源文件。

## 画布与数据源界面

插件在侧栏增加“分析画布”和“数据源”两个工作区：

- 画布工作区显示画布列表和当前画布；卡片使用 96 列网格布局，可拖动、缩放、排序、筛选已载入的表格行、复制、跨画布移动或复制，也可折叠内容和隐藏标题栏。
- 支持多选卡片成组移动、对齐和等间距；可使用缩放、适应全部、参考线与吸附、横向扩展、搜索和画布外卡片导航浏览布局。
- 图表卡片使用 ECharts 绘制其 `echarts_option`；主题和六组调色板会影响图表。若 ECharts 模块加载失败，会显示轻量预览。
- 数据源工作区支持导入 CSV / XLSX、重命名和确认删除、浏览字段和每页 100 行预览、配置结构化查询、分页查看查询结果，并将结果作为表格卡片加入所选画布。查询配置与 `datasource_query` 工具共享受限语义。
- PNG 导出会按需分块；HTML 导出为可离线查看的独立快照。HTML 内的图表为静态图像，表格只包含该卡片当前已载入的数据。

## 架构与数据流程

- **宿主侧工具和路由：** `index.js` 注册插件功能；`lib/tools.js` 定义画布与数据源工具，`lib/routes.js` 提供画布、数据源和查询结果的本地 HTTP 路由。
- **数据持久化：** `lib/store.js` 管理画布和撤销 / 重做历史；`lib/data-store.js` 负责数据源导入、预览分页、结构化查询、结果快照及结果加入画布。
- **客户端：** `client-src/` 中的有序源码段由 `scripts/build-client.mjs` 拼接为 DSH 入口 `client.js`。ECharts 则由 `scripts/build-echarts-chunk.mjs` 单独打包为 `client.echarts.js`，运行时按需加载。
- **数据流：** 文件内容以 base64 导入并经过大小与形状限制；规范化数据写入本地数据源存储；工具查询将有口径和完整性信息的结果保存为快照；界面或智能体工具再分页读取，或将结果插入画布。

## 布局引擎

`lib/grid.js` 移植自 xchartsAI 前端的 96 列网格引擎，并保持行为一致，使两边画布的操作方式相同。它由无依赖的纯函数组成，负责碰撞检测、考虑空隙的放置、压缩和整理布局；该模块有独立单元测试。

坐标使用 `{ x, y, w, h }` 网格单位：`x` / `w` 的单位是 96 列中的列，`y` / `h` 的单位是行。

## 开发

```sh
pnpm build:client
pnpm test
```

`pnpm test` 会先构建客户端 bundle，再运行布局、存储、工具和路由测试，以及数据源、客户端渲染、导出、主题、信任边界和撤销 / 重做测试。客户端源码按职责拆分在 `client-src/` 中；`pnpm build:client` 会按 `scripts/build-client.mjs` 的顺序将这些源码段组装成 DSH 要求的单文件 `window.__ModuleLoader__.load()` bundle `client.js`。ECharts 由 `pnpm build:echarts` 独立打包生成 `client.echarts.js`，升级 ECharts 依赖后需重建该文件。`react` 仍由宿主提供，插件不会重复捆绑 React。

### 客户端功能迭代、热加载与本地发布

1. **先确认改动位置。** 查看相关页面、`client-src/` 对应模块和现有客户端测试。浏览器交互放在 `client-src/`，宿主侧工具、路由和存储放在 `index.js` 或 `lib/`。开始前检查 `git status` 和当前版本，避免覆盖已有改动。
2. **按职责扩展源码。** `client-src/` 文件是共享同一个 ModuleLoader factory 作用域的有序源码段，不是独立 ES module。新增源码段时，在 `scripts/build-client.mjs` 的 `sections` 中登记顺序；不要在源码段内添加 `import`、`export` 或额外包装作用域。日常只修改源码段；`client.js` 是生成的运行时文件，不应作为唯一源码编辑。
3. **构建并验证。** 执行 `pnpm build:client` 生成 `client.js`，再运行 `pnpm test`（会先重建客户端）。客户端改动还应检查 `node --check client.js` 和 `git diff --check`。打包前确认测试使用的是新生成的入口，而不是旧 bundle。
4. **开发时热加载。** 只有在同一份 DSH checkout 中运行 `pnpm run dev:web`，且 client-plugin HMR 接收器可用时，客户端插件改动才会自动热加载。开始调试前确认 watcher 正在运行；不要用另起的 Web 服务替代当前 profile。宿主代码或打包产物的更新通常需要重新安装插件并重启当前 profile。
5. **更新本地 profile。** 先递增 `package.json` 版本，再执行 `pnpm pack`；`prepack` 会自动构建客户端，产物为 `data-canvas-dsh-<version>.tgz`。将 Web profile 的本地 `file:` 依赖指向新 tarball，再执行 `pnpm install --offline` 并重启 profile。最后核对已安装版本、`client.js` 与 `client.echarts.js` 的 SHA-256 和原有 Web 端口。同版本 tarball 可能被包管理器缓存；不要只依赖 `--force` 或“安装成功”提示判断更新完成，应使用新版本并比对文件哈希。
6. **提交前收尾。** 检查完整 diff 和工作区状态，只提交本次相关文件；提交说明使用中文，不推送，除非另有明确要求。

#### 迭代时容易重犯的问题

- DSH 客户端入口依赖单文件 `window.__ModuleLoader__.load()` 契约；模块化的是可维护源码，打包时仍要生成兼容入口。未经验证不要改成浏览器原生模块加载。
- `client.js` 是生成产物，发布前应由构建脚本重新生成；新增源码段若未登记到 `sections`，打包和测试可能漏掉它。
- 源码段共享词法作用域，移动声明或调整拼接顺序可能造成运行时引用问题。改完先构建并运行客户端测试；对文件尾部或大段代码做机械整理后，至少再做语法检查和完整测试。
- HMR 接收器可用不代表 watcher 正在构建。确认 `pnpm run dev:web` 实际运行后再依赖热加载；更新 profile 包后要核对安装版本、文件哈希和服务状态。
- 当前 `package.json` 标记为 `private`，`files` 只包含运行所需 bundle，不包含 `client-src/` 和构建脚本。本地迭代通过 tarball 安装；若要公开发布，需先单独评估并调整包发布配置。

## 设计说明

- **有限的数据查询。** 插件支持本地 CSV / XLSX 导入和受限的结构化查询，不执行任意 SQL 或代码；复杂统计仍可由智能体代码完成。
- **图表按需加载。** ECharts 由独立 chunk 提供，减少画布首次加载的工作；若模块无法加载，界面会退回简化预览。
- **数据卡来源必须可追溯。** 图表、表格和指标卡写入时必须提供 `source.dataset` 与 `source.query`；手工数据须在备注中标记“手工/无外部数据源”。更新卡片时可分别修改来源字段，未传字段保持原值。查询结果还保留源数据版本、结果哈希和完整性信息。
- **错误以数据形式返回。** 工具返回结构化错误，路由返回状态和错误代码；错误不会被抛入智能体循环或浏览器。
- **逐步降级。** Web 服务不可用时，画布界面不会挂载，但工具仍可工作；存储不可读时，插件仍会加载，并由每次调用报告实际错误。
